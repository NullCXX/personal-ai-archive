- API 错误先核对当前账户可用模型、请求格式和工具调用支持，不从笼统报错直接认定服务故障。
- Python 包装在哪个环境，脚本就要使用对应解释器；单纯把项目移动到另一个盘不解决环境不一致。
- 仿真运行失败先检查资源路径、依赖版本、模型和策略参数；成功输出评估文件不代表所有指标通过。
- 软件启动问题要保留用户配置。G HUB 故障在历史聊天中得到用户“正常了”的确认；其他问题不能借此一概标为已修复。
- WPS 缓存清理和导致重复生成的根因修复是两件事；清理报告不能代表后续不再产生。
- 飞书命令写入故障曾被历史 AI 定位到宿主执行/防护环节，但没有确认最终恢复；不要宣称已解决。
- 手机照片列表缺少视频，可能需检查连接授权和原片是否在本机；历史请求未证实目标视频已找到。
- 固件烧录需要核对芯片、固件、串口和校验结果；历史 AI 报告 ESP32 烧录成功，设备后续配网与功能仍需验证。

密码恢复、账户验证与防护设置由本人或管理员处理。公开档案不保存任何历史登录信息或控制设备的连接参数。
